# Свадебный планер — описание для разработки

Женя и Катя, свадьба 12.06.2027, SOMA (Воронеж). Приложение пока только для них; позже — для других пар (и, возможно, App Store).

## Где что
- Сайт (PWA): https://evgakimenko.github.io/wedding/ — GitHub Pages, ветка `main`, корень репозитория.
- Репозиторий: `evgakimenko/wedding`. Корень = опубликованный сайт (собранные файлы), `dev/` = исходники и тесты.
- База и вход: Supabase, проект `gfyelmlqldpfkjoxdltf` (Frankfurt). `config.js` — URL и publishable-ключ (публичный).
- Схема БД и правила доступа: `setup.sql` (уже применён). Менять схему = прислать пользователю SQL для SQL Editor.

## Стек и архитектура
- Один файл `dev/app.src.html` (HTML + CSS + vanilla JS), без фреймворков. `dev/tpl.json` — шаблоны (категории, задачи, покупки, периоды) — вклеивается при сборке.
- Библиотеки лежат локально: `vendor/supabase.js` (supabase-js 2.x UMD), `vendor/xlsx.full.min.js` (SheetJS 0.18.5).
- `sw.js` — офлайн-кэш оболочки (запросы к API не кэширует). `manifest.webmanifest`, иконки в `icons/`.
- Данные: таблица `docs (wedding_id, coll, id, data jsonb)` — документное хранилище. Коллекции: `meta/settings`, `categories`, `vendors`, `payments`, `tasks`, `purchases`, `guests`, `tables`, `expenses`, `mbphotos`, `mbcomments`, `schedule`. У подрядчика `items: [{id,title,mode:'sum'|'guest',amount,per,qty:'active'|'yes'|'plan'|'manual',n,approx}]`, `price` = снимок суммы строк (считается на лету через `vPrice`); у платежа `itemId`. Тяжёлые картинки — отдельно и грузятся по требованию: `receipts` (фото чеков), `mbthumb` / `mbimg` (превью/полные фото мудборда); в общий `loadAll` они не попадают.
- Роли (`members`): `p1` жених, `p2` невеста (редактируют), `viewer` (только просмотр). Вход по почте и паролю. Коды приглашения: `edit_code` (вторая половина пары), `view_code` (координатор, родители). RPC: `create_wedding`, `join_wedding`, `invite_codes`, `remove_member`.
- Офлайн: изменения копятся в очереди (localStorage `wp-outbox-<wedding>`), отправляются при появлении сети; кэш данных `wp-cache-<wedding>`. Синхронизация между устройствами: Supabase Realtime + перезагрузка при возврате в приложение и раз в 60 с.

## Разделы
Главная · Подрядчики (кандидаты «Смотрим» → «Выбрать» → договор, платежи и задатки, авто-статусы; «Состав стоимости» — строки суммой или «цена за гостя × гости» (все кроме отказавшихся / придут / план / вручную), пометка «примерно» → «≈» в итогах, платёж можно привязать к строке) · Бюджет (план/факт по категориям, расходы с фото чеков, все платежи, Excel) · Задачи (по срокам до свадьбы, авто-закрытие при договоре, фильтр по Жене/Кате) · Ещё: Атмосфера (7 досок мудборда: фото, ссылки, пожелания/вопросы, «Скопировать для подрядчика»), Расписание дня (тайминг, типовой шаблон), Покупки, Гости, Рассадка, Напитки, Настройки (приглашения, участники, резервная копия JSON).
Удобства: свайп влево → «Удалить», разряды в суммах при вводе, десктопная версия (боковое меню, ≥900px), тёмная тема.

## Сборка и публикация
```
bash dev/build.sh          # собирает index.html и sw.js в корне
git commit && git push     # GitHub Pages обновляется ~1 мин
```

## Тесты (обязательно перед публикацией)
Тестовый стенд повторяет API Supabase поверх настоящего Postgres с `setup.sql`:
1. Postgres 16 локально (порт 5544, сокет /tmp/pg), заглушка `auth.uid()` из `request.jwt.claim.sub`, роли `anon`/`authenticated`, затем `setup.sql`, плюс `create schema authx; create table authx.users(id uuid primary key default gen_random_uuid(), email text unique not null, pw text not null);` — база `sbt`.
2. `cd dev/testsrv && npm i && node server.js <путь к корню сайта> 8000` — эмулятор PostgREST/Auth (eq, neq, in, not.in, upsert, delete, rpc) и раздача сайта; `config.js` подменяется на локальный.
3. Playwright (Python): `dev/tests/test_web.py` (47 сценариев: вход, роли, приглашения, кандидаты, офлайн, перенос), `test_desktop.py` (22), `test_swipe_exp.py` (28: свайпы, расходы, чеки), `test_mood.py` (24: мудборд, расписание), `test_money.py` (10: ввод сумм), `test_items.py` (30: состав стоимости, примерные суммы, гости, Excel). `rls_test.sql` запускать на чистой базе (считает все строки `docs`). `rls_test.sql` — 12 проверок прав доступа.

## Ограничения
- Пуш-уведомлений нет (напоминания внутри приложения).
- Фото (чеки, мудборд) — только онлайн; в резервную копию JSON не входят.
- Supabase во Франкфурте — у части российских провайдеров возможны перебои; спасает офлайн-очередь.

## Бэклог
1. **Онлайн-приглашение с RSVP** (план согласован, «сделаем позже»): личная ссылка на гостя/семью `…/i/<token>`; страница-приглашение (имена, дата, SOMA с картой, тайминг, дресс-код); «Приду / Не смогу», +1 с именем, дети, меню/аллергии, трансфер, комментарий; ответ автоматически меняет статус гостя, +1 становится отдельным гостем; на главной «Новые ответы»; дедлайн изменения ответа. Реализация: SECURITY DEFINER RPC `rsvp_get(token)` / `rsvp_submit(token, …)` для анонимов — гость видит и меняет только свою запись. Нужен доп. SQL. Позже — уведомления в Telegram-бот.
2. Загрузка фото договоров в карточку подрядчика.
3. Мультиаренда для других пар / App Store.
